## Intent

**Problem:** There is no code yet. Every later story needs a working backend, frontend, database and test harness, all served from one origin.

**Approach:** Create a `uv` Python 3.14 backend package `hoctap` (FastAPI, SQLAlchemy, Alembic) and a Vite React-TS PWA frontend (scaffolded with `@vite-pwa/create-pwa` react-ts and upgraded to the pinned versions). FastAPI serves the built `frontend/dist` at `/` and the API at `/api/v1`. Startup creates `data/hoctap.db` in WAL mode and runs Alembic migrations.

## Boundaries & Constraints

**Always:**
- Use the Stack versions from the architecture spine: Python 3.14, FastAPI 0.141.1, Uvicorn 0.54.0, Pydantic 2.13.5, SQLAlchemy 2.1.1, Alembic 1.20.0, PyMuPDF 1.28.2, anthropic >=1.8,<2, React 19.3.0, Vite 8.3.1, @vitejs/plugin-react 6.1.1, TypeScript 6.0.3, vite-plugin-pwa 1.3.0, TanStack Query 5.104.0, React Router 8.4.0.
- Use the module folders `content`, `learning`, `parent`, `builder`, `api` and `db` under `backend/hoctap/`. Routers hold no logic.
- Errors use the envelope `{"error":{"code","message"}}`. Logs are JSON lines in `data/logs/`. Config comes from `hoctap.toml` plus `HOCTAP_*` environment variables.
- `data/` is gitignored. The code must run on Windows and Linux (use `pathlib`, no POSIX-only calls).

**Never:**
- No business tables yet. Alembic starts with an empty baseline revision.
- No auth, TLS or Docker in this story.
- No hand-written API types: they are generated by openapi-typescript.

## Implementation Notes

- Scaffold was generated with `@vite-pwa/create-pwa@1.1.0` (react-ts, generateSW, prompt-for-update, PWA assets on the fly), then upgraded to the pinned Stack versions. Vitest uses jsdom 27 (jsdom 30 needs Node >= 24.15).
- `openapi-typescript` 7.13.0 (latest) declares a `typescript ^5` peer; `package.json` `overrides` points it at TS 6.0.3. It generates correctly.
- `frontend/openapi.json` and `frontend/src/api/schema.d.ts` are committed, so `gen:api` and `build` work offline. `gen:api` prefers the live server and falls back to the file.
- The SPA fallback is a catch-all route: `/api/*` becomes a JSON 404; a missing file with an extension (e.g. `/assets/x.js`) returns 404 rather than `index.html`. `index.html`, `sw.js` and the manifest are sent with `Cache-Control: no-cache`. Settings also gained `frontend_dist` (`HOCTAP_FRONTEND_DIST`) for tests.

### 2026-10-01: Fix for finding #26 (Orchestrator's Independent Audit)

`create_app()` in `backend/hoctap/app.py` now constructs `FastAPI(..., docs_url=None, redoc_url=None, openapi_url=None)`, closing `/docs`, `/redoc` and `/openapi.json` as unauthenticated endpoints reachable at all times via `hoctap serve`. This is a single-deployment-mode app (one `hoctap serve` path, no separate dev/prod builds), so the flags are unconditional rather than settings-gated -- there is no scenario where they should be on. `backend/hoctap/cli.py`'s `export-openapi` command (`_export_openapi`, line ~113) was confirmed to call `create_app(load_settings()).openapi()` in-process -- it never hits the HTTP route -- so it is unaffected; re-running it reproduced a byte-identical `frontend/openapi.json`. With the routes unregistered, `/docs` and `/redoc` now fall through to the existing SPA catch-all (serving the normal app shell, 200, same as any other unknown client route) and `/openapi.json` 404s with the standard JSON error envelope; none of the three leak API surface. No existing test asserted on these paths. See Review Triage Log #26 for verification detail.
